Техніки бізнес-аналізу

Джерело: A Guide to the Business Analysis Body of Knowledge® (BABOK® Guide), Version 3, International Institute of Business Analysis

Призначення Посилання
Acceptance and Evaluation Criteria Критерії приймання та оцінки Критерії приймання використовуються для визначення вимог, результатів або умов, які мають бути виконані, щоб рішення вважалося прийнятним для ключових зацікавлених сторін.
Критерії оцінки — це метрики, що використовуються для оцінювання набору вимог з метою вибору між кількома рішеннями.
Техніка 10.01 (детально)
Backlog Management Управління беклогом Для фіксації, відстеження та пріоритезації завдань, що залишилися невиконаними.
Техніка 10.02 (детально)
Balanced Scorecard Збалансована система показників Для управління ефективністю в будь-якій бізнес-моделі, організаційній структурі або бізнес-процесі
Техніка 10.03 (детально)
Benchmarking and Market Analysis Бенчмаркінг та аналіз ринку Для покращення діяльності організації, підвищення задоволеності клієнтів і збільшення цінності для зацікавлених сторін.
Техніка 10.04 (детально)
Brainstorming Мозковий штурм Для генерації великої кількості нових ідей та визначення на їх основі напрямів для подальшого аналізу. Спосіб застосування творчого підходу до розв’язання проблеми.
Техніка 10.05 (детально)
Business Capability Analysis Аналіз бізнес-можливостей Для визначення обсягу та планування шляхом формування спільного розуміння результатів діяльності, визначення відповідності стратегії та забезпечення фільтрації змісту й пріоритетів.
Техніка 10.06 (детально)
Business Cases Бізнес-кейс Для обґрунтування плану дій на основі порівняння вигод, що забезпечує запропоноване рішення, з витратами, трудовими затратами та іншими чинниками, пов’язаними з придбанням і використанням цього рішення.
Техніка 10.07 (детально)
Business Model Canvas Канва бізнес-моделі Для опису того, як підприємство створює, надає та отримує цінність для своїх клієнтів і від них.
Техніка 10.08 (детально)
Business Rules Analysis Аналіз бізнес-правил Для виявлення, формулювання, валідації, уточнення та організації правил, що визначають повсякденну діяльність бізнесу та спрямовують процес прийняття операційних бізнес-рішень.
Техніка 10.09 (детально)
Collaborative Games Групові ігри Для заохочення учасників до співпраці задля формування спільного розуміння проблеми або рішення.
Техніка 10.10 (детально)
Concept Modelling Модель понять Для систематизації бізнес-лексикону, необхідного для узгодженого та ґрунтовного передавання знань про предметну область.
Техніка 10.11 (детально)
Data Dictionary Словник даних Для стандартизації визначень елементів даних та забезпечення єдиного розуміння цих елементів.
Техніка 10.12 (детально)
Data Flow Diagrams Діаграми потоків даних Для відображення звідки надходять дані, які види діяльності їх обробляють, а також чи зберігаються результати обробки або використовуються іншими видами діяльності чи зовнішніми сутностями.
Техніка 10.13 (детально)
Data Mining Добування даних Для покращення процесу прийняття рішень шляхом виявлення корисних закономірностей та ідей у даних.
Техніка 10.14 (детально)
Data Modelling Модель даних Для покращення процесу прийняття рішень шляхом виявлення корисних закономірностей та ідей у даних.
Техніка 10.15 (детально)
Decision Analysis Аналіз рішень Для оцінки проблеми та можливих рішень з метою визначення цінності альтернативних результатів в умовах невизначеності.
Техніка 10.16 (детально)
Decision Modelling Модель рішень Показує, як приймаються повторювані бізнес-рішення.
Техніка 10.17 (детально)
Document Analysis Аналіз документів Для виявлення інформації бізнес-аналізу, зокрема для розуміння контексту та вимог, шляхом вивчення доступних матеріалів, що описують бізнес-середовище або наявні активи організації.
Техніка 10.18 (детально)
Estimation Оцінювання Для прогнозування витрат і трудовитрат, пов’язаних із реалізацією певного напряму дій.
Техніка 10.19 (детально)
Financial Analysis Фінансовий аналіз Для розуміння фінансових аспектів інвестиції, рішення або підходу до реалізації рішення.
Техніка 10.20 (детально)
Focus Groups Фокус-група Для виявлення ідей і думок щодо конкретного продукту, послуги або можливості в інтерактивному груповому середовищі. Учасники під керівництвом модератора діляться своїми враженнями, уподобаннями та потребами.
Техніка 10.21 (детально)
Functional Decomposition Функціональна декомпозиція Допомагає керувати складністю та зменшувати невизначеність шляхом розкладання процесів, систем, функціональних областей або результатів на простіші складові, що дає змогу аналізувати кожну з них окремо.
Техніка 10.22 (детально)
Glossary Глосарій Визначає ключові терміни, що стосуються предметної області бізнесу.
Техніка 10.23 (детально)
Interface Analysis Аналіз інтерфейсів Для визначення того, де, що, чому, коли, як і для кого здійснюється обмін інформацією між компонентами рішення або через межі рішення.
Техніка 10.24 (детально)
Interviews Інтерв’ю Для виявлення інформації бізнес-аналізу шляхом спілкування з однією особою або групою осіб, постановки відповідних запитань і документування відповідей.
Також може використовуватися для налагодження взаємовідносин і формування довіри між бізнес-аналітиками та зацікавленими сторонами з метою підвищення їх залученості або підтримки запропонованого рішення.
Техніка 10.25 (детально)
Item Tracking Відстеження питань Для фіксації проблем і занепокоєнь зацікавлених сторін, що впливають на рішення, а також призначення відповідальних за їх опрацювання.
Техніка 10.26 (детально)
Lessons Learned Аналіз отриманого досвіду Для узагальнення та документування успіхів, можливостей для вдосконалення, невдач і рекомендацій щодо підвищення ефективності майбутніх проєктів або їх етапів.
Техніка 10.27 (детально)
Metrics and Key Performance Indicators (KPIs) Метрики та ключові показники ефективності (КРІ) Для вимірювання ефективності рішень, компонентів рішень та інших аспектів, що становлять інтерес для зацікавлених сторін.
Техніка 10.28 (детально)
Mind Mapping Ментальні карти Для формулювання та фіксації думок, ідей та інформації.
Техніка 10.29 (детально)
Non-Functional Requirements Analysis Аналіз нефункціональних вимог Досліджує вимоги до рішення, які визначають, наскільки добре мають виконуватися функціональні вимоги. Він встановлює критерії, за якими можна оцінити роботу системи, а не конкретну поведінку системи, що визначається функціональними вимогами.
Техніка 10.30 (детально)
Observation Спостереження Для виявлення інформації шляхом спостереження за діяльністю та розуміння її контексту. Слугує основою для визначення потреб і можливостей, розуміння бізнес-процесу, встановлення стандартів ефективності, оцінювання ефективності рішення або підтримки навчання та розвитку.
Техніка 10.31 (детально)
Organizational Modelling Модель організаційної структури Для опису ролей, обов’язків і структур підпорядкування, що існують в організації, та узгодження цих структур із цілями організації.
Техніка 10.32 (детально)
Prioritization Пріоритезація Для сприяння прийняттю рішень зацікавленими сторонами та розуміння відносної важливості інформації бізнес-аналізу.
Техніка 10.33 (детально)
Process Analysis Аналіз процесів Для оцінки процесу з погляду його ефективності та результативності, а також здатності виявляти можливості для змін.
Техніка 10.34 (детально)
Process Modelling Модель процесів Для відображення того, як виконується робота, та є основою для аналізу процесів.
Техніка 10.35 (детально)
Prototyping Прототипування Для виявлення та валідації потреб зацікавлених сторін за допомогою ітеративного процесу створення моделі або дизайну вимог.
Також використовується для оптимізації користувацького досвіду, оцінювання варіантів дизайну та як основа для розроблення остаточного бізнес-рішення.
Техніка 10.36 (детально)
Reviews Рецензування (Рев’ю, Перевірка) Для оцінювання змісту результату роботи.
Техніка 10.37 (детально)
Risk Analysis and Management Аналіз та управління ризиками Для виявлення областей невизначеності, які можуть негативно вплинути на цінність, аналізу й оцінювання цієї невизначеності, а також визначення способів реагування на ризики та управління ними.
Техніка 10.38 (детально)
Roles and Permissions Matrix Матриця ролей та повноважень Для забезпечення охоплення видів діяльності шляхом визначення відповідальності, ідентифікації ролей, виявлення відсутніх ролей та інформування про результати запланованої зміни.
Техніка 10.39 (детально)
Root Cause Analysis Аналіз першопричин Для виявлення та оцінювання основних причин проблеми.
Техніка 10.40 (детально)
Scope Modelling Модель меж Для визначення характеру однієї або кількох меж та віднесення елементів до тих, що перебувають усередині або поза цими межами.
Техніка 10.41 (детально)
Sequence Diagrams Діаграми послідовності Для моделювання логіки сценаріїв використання шляхом відображення обміну інформацією між об’єктами системи під час виконання сценарію.
Техніка 10.42 (детально)
Stakeholder List, Map, or Personas Список, карта або персони зацікавлених сторін Для аналізу зацікавлених сторін та їхніх характеристик з метою виявлення всіх можливих джерел вимог і визначення оптимальних способів їх залучення, взаємодії та комунікації.
Техніка 10.43 (детально)
State Modelling Модель станів Для опису й аналізу різних можливих станів сутності в системі, переходів між цими станами та того, що може відбуватися із сутністю в кожному з них.
Техніка 10.44 (детально)
Survey or Questionnaire Опитування або анкетування Для структурованого виявлення інформації бізнес-аналізу, зокрема про клієнтів, продукти, робочі практики та ставлення, від групи людей за відносно короткий проміжок часу.
Техніка 10.45 (детально)
SWOT Analysis SWOT аналіз Для оцінювання сильних і слабких сторін організації, а також можливостей і загроз, зумовлених внутрішніми та зовнішніми умовами.
Техніка 10.46 (детально)
Use Cases and Scenarios Варіанти використання та сценарії Для опису того, як особа або система взаємодіє з модельованим рішенням для досягнення певної мети.
Техніка 10.47 (детально)
User Stories Користувацькі історії Для стислого опису функціональності або якості, необхідної для забезпечення цінності конкретній зацікавленій стороні.
Техніка 10.48 (детально)
Vendor Assessment Оцінювання постачальника Для оцінювання здатності постачальника виконувати зобов’язання щодо постачання та стабільного надання продукту або послуги.
Техніка 10.49 (детально)
Workshops Робочі сесії Для об’єднання зацікавлених сторін з метою спільної роботи над досягненням заздалегідь визначеної мети.
